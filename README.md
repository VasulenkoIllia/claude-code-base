# claude-code-base

База налаштувань Claude Code для macOS: глобальні правила, хуки-охоронці, правила за шляхами, скіли, агенти-рев'юери й інструменти. Вони ставляться в `~/.claude` копією одного тегу, з маніфестом, знімком попереднього стану і відкатом однією командою. Це публічний експорт моєї робочої бази: те саме, крім особистого. Правила й скіли написані англійською (так вони займають менше токенів) і просять Claude відповідати українською; повідомлення хуків українською.

English: [README.en.md](README.en.md).

## Що всередині

| Тека | Що там | Куди ставиться |
|---|---|---|
| `global/` | глобальні правила, `settings.json` з хуками й дозволами, `home-agents.md`, рядки git ignore | `~/.claude/CLAUDE.md`, `~/.claude/settings.json`, `~/AGENTS.md`, `~/.config/git/ignore` (рядки лише дописуються) |
| `hooks/` | bash-guard (питає чи не пускає небезпечні команди: знищення даних, обхід git-хуків, підміну автора, секрети в коміті), secret-guard (секрет у промпті), commit-leaks (gitleaks у кожному коміті, його запускає git), push-allow (push у feature-гілку без запиту), dup-guard, doc-reminder, session-hint, node-std, nvm-env, docs-sync; тести `test-all.sh` | `~/.claude/hooks/` |
| `rules/own/` | правила, які вантажаться, коли Claude торкається файлів з їхніх `paths:` (backend, frontend, БД, deploy, залежності, чистий код, Python, демо) | `~/.claude/rules/` |
| `skills/` | new-project (проєкт за стандартом: Node, pnpm, Docker), client-tz (ТЗ і кошторис у Word), time-register (реєстр часу сесій і оцінки), 3 скіли ECC | `~/.claude/skills/` |
| `agents/` | рев'юери: code-reviewer, security-reviewer, typescript-reviewer, react-reviewer, database-reviewer, architect (ECC), silent-failure-hunter (Anthropic) | `~/.claude/agents/` |
| `tools/` | claude-time (час сесій за проєктами й задачами), claude-metrics (метрики роботи до і після релізів) | `~/bin/` |
| `vendor/ecc/` | звідки кожен скіл і агент ECC, локальні відмінності (`patches/`) | `ECC-PIN.md` у `~/.claude/` |
| `scripts/`, `tests/` | install, rollback, doctor, verify, знімки, project-doctor; тести й гейти | не ставляться (крім `legacy/ecc-drift.sh` у `~/bin/`) |

Що робить кожен хук, скрипт і інструмент, кажуть їхні заголовки. Перелік керованих файлів виводиться з розкладки репо (`scripts/lib.sh`, `managed_items`). Решту `~/.claude` install не чіпає: плагіни, `~/.claude.json`, транскрипти, memory, свої скіли, агенти й правила з іншими назвами. Проєктів install не шукає і не чіпає: правила, хуки, агенти й скіли діють глобально, у сесії в будь-якій теці. Теку проєктів `~/WebstormProjects` читають лише claude-time, claude-metrics, перевірки проєктів у doctor (інша тека: `PROJECTS_DIR`) і docs-sync, коли ви його підключите.

## Вимоги

- macOS на Apple Silicon з Homebrew: хуки беруть `/opt/homebrew/bin/python3` і gitleaks звідти.
- Claude Code: застосунок або CLI.
- Інструменти:

  ```bash
  brew install git jq gitleaks shellcheck python coreutils
  ```

  Перевірка: `uname -m` друкує `arm64`; `git --version` 2.54 чи новіший (з цієї версії git сам запускає commit-leaks на кожен коміт); `python3 --version` 3.11 чи новіший; `command -v python3` друкує `/opt/homebrew/bin/python3` (Homebrew першим у PATH).

  Якщо `command -v python3` друкує інший шлях, типова причина така: раніше ви ставили Python з python.org, його інсталятор дописав свою теку на початок PATH у `~/.zprofile`, а Homebrew в оболонці не підключений. Як виправити: закоментуйте той рядок у `~/.zprofile`, додайте туди рядок `eval "$(/opt/homebrew/bin/brew shellenv)"` і відкрийте новий термінал.
- nvm для Node проєктів: хук nvm-env і `/new-project` беруть його з `~/.nvm/nvm.sh`.

  ```bash
  brew install nvm
  ```

  Потім допишіть у `~/.zshrc` два рядки, які радить `brew info nvm` (`export NVM_DIR="$HOME/.nvm"` і рядок, що завантажує `/opt/homebrew/opt/nvm/nvm.sh`), і відкрийте новий термінал: перше завантаження саме створює `~/.nvm/nvm.sh`. Перевірка: `[ -s ~/.nvm/nvm.sh ] && echo ok` друкує `ok`.
- Для `/new-project` ще `brew install uv osv-scanner` і Docker Desktop.
- Context7 для документації бібліотек (його кличуть глобальні правила): конектор Context7 у claude.ai (Settings, Connectors) або в CLI `claude mcp add --scope user --header "Authorization: Bearer <ключ>" --transport http context7 https://mcp.context7.com/mcp` з ключем з context7.com. Без нього Claude бере документацію з пам'яті моделі.

## Перше встановлення

Близько 10 хвилин. Install нічого не видаляє: кожен замінений файл лягає в знімок, і повернути все можна однією командою (розділ «Відкат»). Ті самі кроки Claude Code зробить за готовим промптом (розділ нижче).

1. Склонуйте репо поза `~/WebstormProjects` (інструменти вважають кожну теку там проєктом), наприклад у `~/claude-code-base`. Теку заздалегідь не створюйте: її створить `git clone`. Команди наступних кроків уже починаються з `cd ~/claude-code-base`, тож запускати їх можна з будь-якої теки. Адреса на кнопці Code цієї сторінки:

   ```bash
   git clone <адреса цього репо> ~/claude-code-base
   ```

2. План, нічого не пише:

   ```bash
   cd ~/claude-code-base && bash scripts/install.sh "$(git tag --sort=-v:refname | head -n 1)" --dry-run
   ```

   Якщо у `~/.claude` вже є ваші `CLAUDE.md`, `settings.json`, хуки, скіли чи агенти з тими самими назвами, план перелічить їх після рядка `differ from <тег>` і закінчиться кодом 3 і рядком `would stop on the drift above`: для першого встановлення це нормально.
3. Що з тих файлів хочете зберегти (свої правила, мова відповідей), перенесіть в особистий шар (розділ нижче). Решта й так ляже в знімок.
4. Встановлення:

   ```bash
   cd ~/claude-code-base && bash scripts/install.sh "$(git tag --sort=-v:refname | head -n 1)" --force-drift
   ```

   Маніфесту ще немає, тож кожен ваш файл, відмінний від тегу, рахується дрейфом: тому `--force-drift` (якщо план був без дрейфу, прапорець нічого не міняє). Замінене лягає в знімок `~/claude-backups/setup-snapshots/<час>-pre-install-<тег>/replaced/`.
5. Перезапустіть усі сесії Claude: застосунок закрийте й відкрийте знову, `claude` у терміналі теж. Нові правила, хуки й `settings.json` діють лише в нових сесіях.
6. Перевірка:

   ```bash
   cd ~/claude-code-base && bash scripts/doctor.sh --live
   ```

   Очікувано: код 0, `live = <тег>, drift 0`, рядок `commit scan: OK`. WARN про проєкти, документи чи docs-sync це підказки, не збій.
7. У новій сесії попросіть Claude виконати `git commit --no-verify -m test`: bash-guard не пустить команду і скаже чому. Команду має запустити сам Claude, тож напишіть прохання в чаті сесії. У терміналі її не запускайте: bash-guard перевіряє лише команди Claude, і там git виконає її як звичайну.

## Готові промпти для Claude Code

Склонуйте репо (крок 1 вище), відкрийте нову сесію Claude Code у теці `~/claude-code-base` (застосунок: ця тека як проєкт; термінал: `cd ~/claude-code-base && claude`) і вставте промпт. У цій теці діє `.claude/settings.json` репо: install, rollback і `restore.sh --apply` завжди питають дозволу.

Перше встановлення:

```text
Встанови базу налаштувань з цього репо в мій ~/.claude за README.md, розділ «Перше встановлення». Іди по кроках і зупиняйся там, де маю відповісти я. Вивід і код виходу кожної команди зберігай у ~/claude-code-base-report/ (файл на крок: 01-requirements.txt, 02-dry-run.txt, 03-install.txt).
1. Перевір вимоги з розділу «Вимоги» і скажи, чого бракує. Нічого не встановлюй сам.
2. Візьми найновіший тег (git tag --sort=-v:refname | head -n 1) і запусти bash scripts/install.sh <тег> --dry-run. Перекажи план простими словами: що поставиться і які мої файли рахуються дрейфом.
3. Про кожен мій файл з дрейфу скажи, що в ньому моє, і запропонуй, що перенести в ~/.claude/rules/<моє>.md. Переноси лише після мого «так».
4. Після мого окремого «так» запусти bash scripts/install.sh <тег> --force-drift і скажи, де лежить знімок.
5. Попроси мене перезапустити всі сесії Claude і на цьому зупинись.
```

Перевірка в новій сесії після перезапуску:

```text
Перевір базу налаштувань: запусти bash scripts/doctor.sh --live. Очікую код 0, live = <тег>, drift 0 і рядок commit scan: OK; WARN перекажи коротко. Потім спробуй виконати git commit --no-verify -m test і покажи, що відповів bash-guard. Вивід і код виходу збережи в ~/claude-code-base-report/04-doctor.txt і 05-bash-guard.txt.
```

Звіт, якщо я попросив його надіслати (перегляньте теку перед відправкою):

```text
Склади звіт про встановлення бази налаштувань у ~/claude-code-base-report/report.md з файлів цієї теки: дата; macOS і чип; версії git, python3, jq, gitleaks, shellcheck; встановлений тег; що план показав дрейфом і що я переніс в особистий шар; код виходу install і шлях знімка; doctor (код, рядок live, commit scan, WARN); що відповів bash-guard; помилки, незрозумілі кроки і мої питання. Без секретів, токенів і паролів; назви моїх проєктів і клієнтів заміни на «проєкт 1», «проєкт 2», так само в логах теки. Покажи мені звіт і нагадай переглянути всю теку перед відправкою.
```

Оновлення:

```text
Онови базу налаштувань з цього репо за README.md, розділ «Оновлення»:
1. Виконай git pull --ff-only і git fetch --tags. Скажи, який тег у мене живий (jq -r .ref ~/.claude/.setup-manifest.json) і який найновіший (git tag --sort=-v:refname | head -n 1). Якщо вони однакові, на цьому зупинись.
2. Перекажи з CHANGELOG.md, що змінилось між ними.
3. Запусти bash scripts/install.sh <найновіший тег> --dry-run і перекажи план. Якщо є дрейф, покажи файли й запропонуй перенести мої зміни в особистий шар; --force-drift лише з мого окремого «так».
4. Після мого «так» встанови тег без --dry-run, попроси мене перезапустити всі сесії Claude і зупинись.
```

Відкат:

```text
Відкоти базу налаштувань за README.md, розділ «Відкат». Скажи, який тег у мене живий (jq -r .ref ~/.claude/.setup-manifest.json) і на який відкочуємо, покажи план (bash scripts/rollback.sh <тег> --dry-run), а сам відкат запусти лише після мого «так». Потім попроси мене перезапустити всі сесії Claude.
```

## Особистий шар

- Свої правила й уподобання (мова відповідей, стиль, інструменти): `~/.claude/rules/<своє>.md` без `paths:` у frontmatter, такий файл Claude Code вантажить на старті кожної сесії. Назва не має збігатися з правилом бази (`rules/own/`): файл з такою назвою база вважає своїм, і наступний install зупиниться з кодом 3.
- Налаштування й дозволи проєкту: `<проєкт>/.claude/settings.local.json`.
- Керовані файли не правте: зміна це дрейф, `doctor.sh --live` її покаже, а наступний install зупиниться з кодом 3. У `settings.json` пише і застосунок (плагін, дозвіл «завжди», тема), це теж дрейф.

## Оновлення

Нові релізи виходять тегами з моєї приватної бази. `main` тут рухається лише вперед, теги не переносяться й не видаляються, тож `git pull --ff-only` проходить завжди. Те саме Claude Code зробить за промптом «Оновлення» вище.

```bash
cd ~/claude-code-base && git pull --ff-only && git fetch --tags
bash scripts/install.sh "$(git tag --sort=-v:refname | head -n 1)" --dry-run
```

Що змінилось: [CHANGELOG.md](CHANGELOG.md). Якщо план без дрейфу, та сама команда без `--dry-run`, потім перезапуск сесій і `doctor.sh --live`. Дрейф означає, що змінено керований файл: перенесіть зміну в особистий шар, тоді `--force-drift` (змінений файл лишиться в знімку).

## Відкат

Від легшого до важчого. Команди в терміналі працюють і без Claude. Готовий промпт: «Відкат» вище.

1. **Після оновлення щось поводиться дивно:** у теці репо `bash scripts/rollback.sh <попередній тег>` (спершу можна з `--dry-run`), потім перезапуск усіх сесій. Він не зупиняється на дрейфі (змінений файл лишається в знімку) і на попередженнях verify старого тегу під новішими shellcheck чи gitleaks; тести хуків діють і тут.
2. **Claude не може виконати жодної команди** (bash-guard не пускає все або зламався): у чаті попросіть «інструментом Edit прибери ключ `hooks` з `~/.claude/settings.json`», відкрийте нову сесію і зробіть крок 1. Якщо bash-guard питає про кожну команду з причиною «вхід хука не прочитано» чи «хук зупинився», команди йдуть після «так», а причина в `~/.claude/logs/bash-guard.err`.
3. **`rollback.sh` завершився помилкою:** відновіть знімок. `install.sh` робить його перед кожним встановленням, а `restore.sh` у ньому працює навіть без репо:

   ```bash
   ls ~/claude-backups/setup-snapshots/
   bash ~/claude-backups/setup-snapshots/<знімок>/restore.sh
   bash ~/claude-backups/setup-snapshots/<знімок>/restore.sh --apply
   ```

   Перший рядок показує знімки, другий робить пробний прогін (нічого не змінює), третій відновлює і звіряє (MATCH/DIFF). З цілим репо те саме робить `bash scripts/rollback.sh --to-snapshot ~/claude-backups/setup-snapshots/<знімок>`: він спершу знімає поточний стан, тож і цей відкат можна скасувати.
4. **Прибрати базу зовсім:** той самий `restore.sh` зі знімка першого встановлення (`<час>-pre-install-<перший тег>`). `restore.sh` нічого не видаляє: усе, що він замінює чи прибирає, спершу кладе в `displaced-<час>/` того ж знімка. Повернутися на базу потім: `bash scripts/rollback.sh <тег>`.

Дрібні випадки:

- Хибний блок секрету в промпті: додайте `[secret-ok]` на початку чи в кінці повідомлення.
- Нова сесія пропонує оновити Node проєкту: це хук node-std, раз на проєкт і стандарт, лише в новій сесії чи після `/clear`. Пропозицію можна пропустити: вдруге вона не з'явиться до нового стандарту.
- Коміт друкує рядок `docs-sync: …`: коміт і пуш пройшли, не синхронізувались лише документи; причина в рядку і в `~/.claude/logs/docs-sync.err`.
- Один проєкт поводиться не так, як решта: `bash scripts/project-doctor.sh <тека проєкту>` у теці репо, лише читає.

## Облік часу (claude-time)

`~/bin/claude-time` зводить час сесій Claude Code по проєктах у реєстр задач: читає транскрипти `~/.claude/projects`, проєкти і їхні картки бере з `~/WebstormProjects`. Без `--write` нічого не пише; з `--write` дані лягають у приватну теку `~/claude-time` (поза git). Звіти й прапорці: `~/bin/claude-time --help`.

- Скіл `time-register`: попросіть Claude «онови реєстр часу» (поділ нових запитів на задачі і запис) чи «скільки часу піде на …» (оцінка за аналогами з реєстру, лише години сесій Claude).
- `~/bin/claude-metrics`: метрики роботи до і після релізів бази (`--help`); тижневе оновлення показує їх саме.
- Щотижня само: у застосунку Claude (вкладка Code) створіть задачу за розкладом, щопонеділка, тека `~/claude-code-base`, з промптом:

  ```text
  Щотижневе оновлення реєстру часу сесій Claude. Виклич скіл time-register і виконай його розділ 1 крок за кроком: поділи нові запити на задачі і запиши поділ сам, без мого підтвердження; потім звіт і метрики тижня.
  ```

## Документи поза git (docs-sync)

Якщо проєкти тримають документи поза git (`docs/` чи `_internal/` у `.gitignore`, `STATUS*.md` у `.claude/state/`), docs-sync дзеркалить їх в один приватний репо `~/project-docs`: після кожного коміту і перед пушем підключеного проєкту, з перевіркою gitleaks перед кожним комітом репо документів. Тека проєкту лишається джерелом, у дзеркалі нічого не правте. Потрібен git 2.54 чи новіший.

1. Репо документів, один раз:

   ```bash
   ~/.claude/hooks/docs-sync.sh init
   ```

2. Приватна копія на GitHub (далі пуш іде сам у фоні, поки репо попереду origin):

   ```bash
   cd ~/project-docs && gh repo create project-docs --private --source . --remote origin --push
   ```

3. Підключити проєкт: спершу план (скільки файлів і МБ, нічого не пише), потім те саме без `--dry-run`:

   ```bash
   ~/.claude/hooks/docs-sync.sh connect --dry-run ~/WebstormProjects/<тека>
   ~/.claude/hooks/docs-sync.sh connect ~/WebstormProjects/<тека>
   ```

Далі само. Документи змінились без коміту: `~/.claude/hooks/docs-sync.sh sync <тека>`; від'єднати: `disconnect <тека>`; стан: рядки `docs repo:` у `doctor.sh --live`. Новий проєкт `/new-project` підключає сам.

## Звірка з ECC (ecc-drift)

## Відомі межі

- Лише macOS на Apple Silicon з Homebrew. Глобальні правила просять Claude відповідати українською, повідомлення хуків теж українською; інша мова відповідей: своє правило в особистому шарі, але після стискання контексту хук session-hint усе одно нагадує Claude про українську (прибрати це можна лише у своїй копії, [docs/FORK.md](docs/FORK.md)).
- `settings.json` керований повністю: ваші ключі там (плагіни, модель, дозволи) install замінить, а окремого файла налаштувань користувача поруч Claude Code не читає. Особисте лише в `~/.claude/rules/` і в проєктах.
- Проєкти очікуються в `~/WebstormProjects`: там їх шукають claude-time, claude-metrics, doctor (для doctor і project-doctor інша тека через `PROJECTS_DIR`) і docs-sync. claude-metrics не рахує сесій у теці `claude-code-base` (сама база); дні рахує за Києвом, вікна «до» і «після» за замовчуванням з моєї історії (свої: `--before`, `--after`).
- docs-sync, ecc-drift і claude-time нічого не роблять, доки ви їх не запустите чи не підключите (розділи вище).
- Хуки-охоронці страхують від помилок моделі, а не від людини: їхня логіка відкрита.
- Сповіщення про новий тег немає: оновлення вручну. Теги calver `vYYYY.MM.N` з моєї бази, пропуски номерів нормальні.
