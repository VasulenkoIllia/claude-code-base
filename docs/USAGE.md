Посібник на кожен день: що працює само, що казати Claude, що робити щотижня і як почати новий проєкт. Встановлення, оновлення й відкат: [README.md](../README.md). Зміни бази у своїй копії: [FORK.md](FORK.md). Що змінилось: [CHANGELOG.md](../CHANGELOG.md). Команди з `scripts/` запускаються в теці репо, тут `~/claude-code-base`, як у README.

## 1. Що встановлено і що воно робить

**Глобальні правила.** `~/.claude/CLAUDE.md` діє в кожній сесії; AGENTS.md, CLAUDE.md і CLAUDE.local.md проєкту мають пріоритет. Правила, rules і скіли написані англійською, так вони займають менше токенів. Українською лишились тексти для вас (формат підсумку, квіз `/new-project`), тригери на кшталт «проаналізуй» і скіл client-tz. Claude відповідає українською, повідомлення хуків для вас (запит дозволу, блок секрету) теж українською. Інша мова відповідей: своє правило (розділ 6), але після стискання контексту хук session-hint усе одно нагадує Claude про українську; прибрати це нагадування можна лише у своїй копії ([FORK.md](FORK.md), рядок `compact` у `hooks/session-hint.sh`). Головне, що правила кажуть Claude:
- робити лише те, що попросили; ідеї понад задачу одним рядком, без реалізації;
- коміт і пуш лише на прохання в поточному повідомленні; без деплою, force-push і злиття в main без окремого прохання; перед комітом список staged, без `git add -A`; без згадок Claude чи AI в комітах, PR і коді;
- серверні команди запускаєте ви: Claude дає їх по одній, спершу читання, перед змінами бекап і відкат, і чекає вашого виводу;
- секретів не друкувати, `.env` не читати: назви ключів з `.env.example`;
- «готово» лише після гейтів проєкту (typecheck, lint, тести, build), підсумок рядком `Змінено: … · Перевірено: … · Не перевірено/не зроблено: … · Ризики: … · Документація: … · Коміт/пуш: … · Міграції/env: … · Сервер: …`;
- одна задача на сесію; на межі етапу оновити STATUS і запропонувати нову сесію.

**Правила за шляхами** (`~/.claude/rules/`). Claude отримує файл, лише коли читає файли цих шляхів. Діють для нового й зміненого коду.

| backend.md | API, вебхуки, воркери, боти, парсери, cron | доступ, вебхуки, `response.ok`, ретраї, тести збою |

| deploy.md | Dockerfile, compose, workflows, `*.sh` | томи БД, теги образів, healthcheck, порти |

**Хуки.** Спрацьовують самі. Їхні внутрішні помилки в сесії не видно, їх показує `doctor.sh --live` (розділ 3).
- nvm-env: на старті сесії ставить першим у PATH Node з `.nvmrc`, якщо його вже встановлено через nvm у `~/.nvm`. Нічого не друкує і нічого не встановлює.
- node-std: на старті нової сесії чи після `/clear`, раз на проєкт і мажор стандарту, читає Node у `.nvmrc`, Dockerfile, compose і CI. Якщо він позаду стандарту, без підтримки чи менше ніж за 6 місяців до її кінця або ніде не закріплений, Claude скаже це одним реченням і запропонує окрему задачу оновлення, нічого не міняючи без вашого OK. Потім до нового мажору стандарту мовчить.
- secret-guard: не пропускає ваше повідомлення з явним токеном чи ключем (розділ 2).
- bash-guard: перевіряє кожну shell-команду Claude, блокує або питає (розділ 2).
- dup-guard: після правки .ts, .tsx, .js, .jsx, .mjs, .cjs шукає в репо функцію чи клас зі схожою назвою і тілом і дає Claude підказку з шляхом. Нічого не блокує.
- doc-reminder: коміт Claude з кодом, але без змін документів (README, `docs/`, `*.md`, документи поза git), дає нагадування оновити зачеплені документи до пушу чи деплою. Журнал (STATUS, плани, CHANGELOG, нотатки з датою) документом не рахується. Одне нагадування на серію комітів. Нічого не блокує.
- session-hint: після пушу і після стискання контексту Claude, якщо далі інша задача, пропонує нову сесію з коротким брифом. Після `gh pr create` чекає CI одним фоновим `gh pr checks <номер> --watch` і закінчує хід рішенням про злиття. Нічого не блокує.
- commit-leaks: gitleaks у кожному `git commit` сесії Claude (розділ 2).
- docs-sync: git-хук підключених проєктів, працює і з термінала та IDE (розділ 2).

**Агенти-рев'юери.** Claude кличе їх сам за правилами рев'ю; можна назвати й самому.
- code-reviewer: завжди. Дублі, файли й функції, що виросли, зайві абстракції, те, що забороняє картка «Розмір» (HIGH), мертвий код, імена. Лише нове й змінене.
- typescript-reviewer: типи, DTO, async, публічні контракти.
- react-reviewer: .tsx і .jsx, не Light.
- database-reviewer: Prisma, міграції, SQL; стартує зі скілом database-migrations.
- security-reviewer: auth, вебхуки, платежі, секрети, завантаження файлів; стартує зі скілом security-review.
- silent-failure-hunter: інтеграції, боти, парсери, черги.
- architect: архітектурні рішення, лише читає. Кликати явно.

**Скіли.**
- time-register: «онови реєстр часу», «скільки часу пішло», «скільки часу піде», «оціни в годинах», «трудозатрати» (розділи 3 і 4).
- client-tz: «ТЗ для клієнта», «ТЗ у ворді», «кошторис», «комерційна пропозиція» (розділ 4).
- new-project: лише ручний виклик `/new-project` (розділ 4).
- documentation-lookup: актуальна документація бібліотек через Context7 (конектор: README, «Вимоги»).
- docker-patterns і api-design з'являються самі, коли Claude торкається Dockerfile чи compose або роутів, контролерів, OpenAPI. database-migrations і security-review вантажать рев'юери.
- Вбудовані в Claude Code: `/simplify` (спрощує дифф), `/code-review` (шукає баги в диффі).

**Інструменти в `~/bin`.** claude-time: реєстр задач і часу сесій. claude-metrics: метрики «до і після», лише читає. ecc-drift.sh: розбіжність скілів і агентів ECC з upstream.

**Дозволи** (`permissions` у `global/settings.json`).
- Без питань: `git status`, `diff`, `log`, `show`; typecheck, lint, test і build через `npm run`, typecheck, lint і test через `pnpm run`; `docker ps` і логи; `gh pr view` і `checks`, `gh run`; `osv-scanner scan`; claude-time і claude-metrics.
- З питанням: `git push`, `gh pr merge`, ssh, scp, rsync, `prisma migrate reset` і `db push`; прямі правки керованих файлів `~/.claude` і `~/bin`.
- Заборонено: `git push --force`, `osv-scanner fix`, читання `.env` і подібних (список у `permissions.deny`), `~/.ssh`, `~/.aws`. Інші `.env.*` закриває запит bash-guard на cat, head, tail.
- Атрибуції Claude у комітах і PR немає. Транскрипти Claude Code зберігає 180 днів: з них беруть дані claude-time і claude-metrics.

## 2. Щоденна робота

**Старт задачі.**
1. Нова сесія в теці проєкту, одна задача на сесію. Коли Claude пропонує винести наступну задачу в нову сесію (у застосунку це картка), відповідайте на самій картці: нове повідомлення, поки картка відкрита, застосунок рахує відмовою.
2. Перший запит починайте з `задача: <коротка назва>`: так реєстр часу бачить нову задачу.
3. Claude сам читає картку «Розмір» проєкту (розділ 5): від неї залежать обсяг рішення і перевірки.
4. Велика зміна: спершу план і список файлів. Перед продом, деплоєм і видаленням Claude чекає вашого слова.
5. «Проаналізуй», «аргументуй», «поки нічого не роби», «просто питання»: лише аналіз, без правок.

**Чистий код і рев'ю.** clean-code.md вантажиться з першим прочитаним файлом коду, code-reviewer перевіряє ті самі пороги в диффі, рядок «Перевірено» підсумку називає рев'ю або каже, що його не було. Наявний код Claude не переписує: порушення лише назве, рефакторинг за вашим рішенням. Пороги проєкту (його CLAUDE.md, ESLint) мають пріоритет.
- Light-зміна (до ~50 рядків, без БД і auth): лише code-reviewer. Більша: кілька рев'юерів паралельно, не більше 4.
- Рев'юери лише звітують, правки робить основна сесія. Перед «готово» великої зміни можна сказати `/simplify`.

**Браузер.** Для UI Claude сам відкриває вбудований браузер. Логін на сайтах робите ви; Claude входить лише під тестовим акаунтом локальної БД чи моків і пароля не виводить. Перевірку від 5 кроків він віддає субагенту `Explore`: той стартує з малим контекстом і повертає висновок і числа. Пропустив: «перевір у субагенті». Для проєкту з UI B (працює на телефоні) вузька ширина обов'язкова; пропустив: «перевір на 390».

**Документація.** Входить у «готово»: зачеплені документи, також поза git, Claude оновлює до коміту, пушу чи деплою і називає їх у полі «Документація:» підсумку. Не може записати (worktree, хук, доступ): одразу питає вас. У документах немає живих фактів (лічильники, sha, стан пушу, номери рядків), лише посилання на файл чи команду. Проєкти з документами поза git (`docs/` у `.gitignore`, `_internal/` у `.git/info/exclude`): нові сесії без worktree, якщо ви не просите. Пропустив: «онови документацію».

**Документи поза git (docs-sync).** Створити репо документів `~/project-docs` і підключити проєкт: README, «Документи поза git». У репо лише дзеркало, джерело в теці проєкту: там нічого не правте.
- Копіюються `docs/` і `_internal/` основної теки, у яких немає трекнутих файлів і свого репо, та `STATUS*.md` з `.claude/state`. Не копіюються приховані файли, `node_modules`, ключі (`*.pem`, `*.key`, `id_rsa*` та подібні), посилання і файли понад 50 МБ.
- Після коміту і перед пушем підключеного проєкту хук копіює документи основної теки (коміт у worktree теж), комітить у `~/project-docs` і пушить у фоні без запиту пароля. Коміт і пуш проєкту він ніколи не зупиняє: збій дає рядок `docs-sync: …` у виводі і рядок у `~/.claude/logs/docs-sync.err`; невдалий пуш повторить наступний коміт.
- Перед кожним комітом і пушем репо документів працює gitleaks з правилами commit-leaks. Знахідка зупиняє лише коміт документів, рядок називає файл і рядок: приберіть секрет, наступний коміт проєкту синхронізує. Зображень, docx, xlsx, pdf і бінарних файлів сканер не бачить, вони йдуть з рядком `not scanned: N`.
- Тека джерела порожня чи за раз зникло понад 20 файлів і понад половину копії: хук нічого не копіює й не видаляє (рядок `Kept`). Видалення справжнє: `docs-sync.sh sync <тека>`. Тека, що вся пішла в git проєкту, зникає з копії сама, історія репо документів її зберігає.
- Документи змінились без коміту: `docs-sync.sh sync <тека>`. Лише рядок реєстру (тека без git): `register <тека>`. Від'єднати: `disconnect <тека>`, копія лишається. Тека переїхала: `connect` на новому місці. Стан: рядок `docs repo:` у doctor і `docs-sync.sh report`.

**Коли bash-guard блокує** (команда не виконується, Claude бачить причину і міняє команду):
- `--no-verify` і скорочення, `-n` у `git commit` і `git am`, `core.hooksPath`, `HUSKY=0`, також усередині `bash -c "…"` чи `ssh host '…'`. Правило шукає `git commit` будь-де в рядку, також у лапках, тож хибно блокує й текст з окремим `-n` (повідомлення коміту, echo, heredoc): тоді переформулювати чи записати текст через Write;
- force push і `+refspec`;
- AI-атрибуція в коміті, PR, issue чи release; ім'я Claude чи Anthropic в авторі коміту чи в git-конфігу репо;
- `rm -r` системних і домашніх тек, також у лапках; `kill -9 -1`;
- gitleaks знайшов секрет у staged під час `git commit`.

**Скан усередині коміту** (commit-leaks). Git сам запускає `hooks/commit-leaks.sh` у кожному `git commit` сесії Claude (ключі `GIT_CONFIG_*` в `env` файла settings.json, потрібен git 2.54 чи новіший) і бачить усе, що коміт реально бере: `git add` у тій самій команді, `git commit -a`, скрипт. Хуки проєктів працюють далі. Коміти з вашого термінала чи IDE без скану: це й вихід, коли скан помилився.
- Знахідка: коміт не пройшов (`BLOCKED by commit-leaks: gitleaks found a secret…`), push через `&&` не виконається, файли лишаються в індексі.
- Скан понад 10 с: коміт не пройшов; такий коміт робіть самі.
- gitleaks немає чи він упав: коміт іде з рядком `commit-leaks: secrets in this commit are not checked`.
- Правила: `hooks/commit-leaks.toml`, усі правила gitleaks, крім того, що `generic-api-key` не читає тести, моки й значення sha256 (там лише хибні збіги); токени відомого формату ловляться і там. Свій `.gitleaks.toml` у корені проєкту замінює цей файл цілком. Хибна знахідка: `# gitleaks:allow` у рядку.
- `git cherry-pick`, `git rebase` і автоматичний merge скану не мають. Сесія, стартована до install, хука не має, поки її не перезапустити.

**Коли bash-guard питає** (приходить запит дозволу):
- коміт чи git-налаштування з іменем, що не збігається з вашим git `user.name` чи `user.email`. Виняток: одноразове репо під `/tmp`, але лише коли з команди напевно видно, що git працює саме там;
- `docker system prune` і `prune` томів, образів і кешу збірки, `docker volume rm`, `docker compose down -v` (томи з e2e, test, tmp, scratch чи sandbox у назві без запиту); `docker compose config` без `-q`, `--services` чи виводу у файл: він друкує секрети з env;
- `prisma migrate reset`, `--accept-data-loss`, `--force-reset`, `prisma migrate resolve`; рядок підключення з паролем до віддаленої БД; DROP, TRUNCATE, dropdb, DELETE без WHERE (крім БД з test чи tmp у назві);
- `curl | sh` в одному рядку, `sudo rm`, `chmod -R 777`, `npm publish`;
- `git reset --hard`, `clean -f`, `checkout .`, `restore .`, `stash drop` і `clear`; `rm -r` по uploads, pgdata, `.git`, migrations, backups, dumps; cat, head, tail для `.env`;
- commit чи merge у main або master, коли в репо є гілка develop чи dev;
- хук не зміг перевірити команду, з рядком у `~/.claude/logs/bash-guard.err`: «вхід хука не прочитано» (на кожну команду: зламаний jq чи Claude Code змінив вхід хука; перевірте `/usr/bin/jq --version` і doctor; з міткою `TimeLimit` команда просто задовга), «хук зупинився» (найчастіше вичерпано ліміт процесів важкими паралельними прогонами), «секрети в staged не перевірено» (перед «так» перевірте вручну `gitleaks git --pre-commit --staged --redact`).

Хук, що перевищив 15 с, завис чи зник, не питає: команда виконується без перевірки, а doctor показує це рядком `hook failures:`. Правила читають текст, що справді виконується (сценарій `sh -c '…'` теж), і за будь-якого сумніву питають. Перед «так» гляньте, чи це локальна БД і чи є бекап; сумніваєтесь: «ні» і попросіть пояснити.

**Секрет у повідомленні.** secret-guard не пропускає повідомлення з явним токеном: замініть значення на `<TOKEN>`, справжнє покладіть у `.env` (на сервері через `read -rs`). Хибний блок: рядок `[secret-ok]` на початку чи в кінці повідомлення. Секрет усе ж потрапив у чат: змініть його (ротація).

## 3. Щотижня

**Реєстр часу.** Задачу за розкладом створюєте один раз (README, «Облік часу»). Щотижня вона викликає скіл time-register: той оновлює реєстр, сам ділить нові запити на задачі й записує поділ, далі звіт: що записано, рядки «сумнів:», межа поділу, години за проєктами й тижнями, метрики. Вручну те саме: «онови реєстр часу і покажи метрики тижня».
- Mac спав чи застосунок був закритий у час запуску: після пробудження буде один запуск за пропущене, нічого не губиться. Від сну в простої: Settings, This computer, System, Keep computer awake.
- Сесія йде без запитів: команди claude-time і claude-metrics дозволено, а скіл запускає кожну окремим простим викликом. Якщо все ж питає, схваліть.
- Сумнівний поділ записується з найкращою здогадкою і приміткою «сумнів:». Знайти такі задачі: `~/bin/claude-time --by task --grep 'сумнів'`. Переділити вже поділене Claude може лише на ваше прохання.
- «увага:» сесія переказує дослівно. «увага:» до запису зупиняє поділ: нічого не записано, наступний запуск почне з тієї ж межі. «увага: реєстр не записано: …» означає, що змінився формат транскриптів Claude Code: напишіть issue.
- Запит, що починається з «<» (набраний `<div>`, «<3»), запитом не рахується і дає рядок «примітка:». Починайте запит словом.
- Пауза, запуск зараз, історія: у застосунку Claude розділ Routines бічної панелі (Status, Run now, Review history), або в сесії «покажи задачі за розкладом».
- Години це час сесій Claude, паузи понад 30 хв не рахуються; дзвінки й робота поза сесіями лише з ваших слів. «Сума» більша за «годинник», коли сесії йшли паралельно. У назвах задач без секретів, email, телефонів і хостів.

**Метрики claude-metrics.** Вікна «до» і «після» за замовчуванням задані датами моєї історії («до» з 2026-08-01 по 2026-09-30, «після» з 2026-10-13). У вас там, найімовірніше, немає транскриптів, тож задайте свої: `--before <від> <до> --after <від> <до>`, дати `YYYY-MM-DD`. Без вікон корисний `--weekly`: ключові метрики по тижнях. Кандидати «переробити» і «готово, а потім баг» для вашої розмітки: `--candidates`. Що рахується: заголовок `tools/claude-metrics.py`. Порівняння має сенс від 5 активних днів у вікні, про менше звіт попереджає. Головне: розмір контексту і стискання, перезапис кешу після паузи, рев'ю комітів, «спрости» і переробки, запити дозволу, старт сесії. «увага:» означає, що метрики неповні.

**Стан бази.** `bash scripts/doctor.sh --live --skip-tests` лише читає. Добрий стан:
- `live = <тег>, drift 0`;
- немає рядків `internal errors` і `input of an unknown shape` (dup-guard, doc-reminder, session-hint, bash-guard, node-std);
- `commit scan: OK`: справжній коміт з вигаданим токеном у тимчасовому репо зупиняється;
- `delivery:` з PASS; одразу після install там NOT PROVEN YET чи NO DATA, доки нові сесії не мали пушу і стискання, і це не збій;
- `hook failures:` 0 за 7 днів. Зі збоями WARN каже, скільки, яких видів і де. Збій fork означає, що скінчився ліміт процесів: шукайте важкі паралельні прогони в той час. Рядок очиститься сам, коли збою мине 7 днів.

Решта WARN про проєкти в `~/WebstormProjects` (інша тека: `PROJECTS_DIR=<тека>`), а не про базу: завеликі CLAUDE.md, AGENTS.md чи STATUS (`project file over 30 KB`, `STATUS over 60 lines`), `README behind the code`, активний проєкт без інструкцій чи картки, Node позаду стандарту чи без підтримки (рядок `stack:`; оновлення запропонує node-std у сесії проєкту), `docs repo:` (docs-sync). Кожен проєкт окремою сесією; усі прапорці: `bash scripts/project-doctor.sh --all`.

## 4. Новий проєкт: оцінка, ТЗ і старт

**Години.** «Оціни в годинах: <опис або шлях до ТЗ>». time-register ділить роботу на пункти з типом (module, integration, ui, ops, docs, bug), не забуває аналіз, ТЗ, деплой, тестування і правки клієнта, бере медіану і p75 за типом з вашого реєстру, шукає схожі задачі і дає вилку. Це години сесій Claude, без дзвінків і очікування клієнта; календарний строк довший. Тип, де менше 5 задач, позначено «мало даних», тож перші тижні оцінки грубі. Щоб Claude ніколи не називав цифр без реєстру, допишіть у `~/.claude/rules/<своє>.md` рядок: `Time or effort estimates (hours, days) only via the time-register skill, with register analogs and median/p75; no figures from your head.`

**ТЗ, КП чи кошторис у Word.** «Зроби ТЗ для клієнта у ворді». Скіл client-tz пише Markdown за структурою ТЗ етапу (що входить і не входить, план, години й ціна, строки, правки, питання), ставку й формулу ціни бере лише з ваших слів чи картки, збирає .docx і PDF: `python3 -I ~/.claude/skills/client-tz/md2docx.py <файл>.md <файл>.docx --strict --pdf`. `--strict` зупиняється на довгих тире ще до запису, `--pdf` рахує сторінки (потрібен LibreOffice). Текст для клієнта: прості слова, без довгих тире й емодзі, від першої особи однини. Перед відправкою перегляньте PDF.

**Старт проєкту (`/new-project`).** Сесія Claude в теці проєкту, яка б вона не була, і `/new-project`; бриф у тому ж повідомленні, наступним чи в `brief/`. Потрібні nvm, uv, osv-scanner і Docker Desktop; Node стандарту й pnpm Claude поставить з вашого OK.
1. Тека. Назва малими латинськими літерами, цифрами й дефісом: вона стане назвою застосунку, проєкту compose і БД. Режим Claude визначає сам (нижче).
2. Контекст, до будь-яких файлів. Claude читає бриф і одним повідомленням питає, чого не знає: мета й користувачі, етап (демо, пілот, прод) і успіх етапу, дані й обсяги, інтеграції, особливі частини (векторний пошук, LLM, файли, оплати, ролі, телефон), бюджет платних API, що поза обсягом.
3. Паспорт на один екран: що Claude зрозумів, рекомендації (тип, каркас, БД, UI) з причинами, картка, нестандартне, рядок «Документи» (що піде в `~/project-docs`), відкриті питання. Кнопки «Так, далі» (це ще й OK на docs-sync) і «Змінити».
4. Квіз лише про розвилки й лише після вашої відповіді на паспорт.
5. Claude створює каркас, картку `CLAUDE.local.md`, STATUS з архівом у `.claude/state/` і репо на `main`, ставить пакети, перевіряє їх osv-scanner (шкідливий пакет, CRITICAL чи HIGH у продовій залежності зупиняють), проганяє `pnpm run check` (typecheck, lint, тести, build) і docker build, перевіряє, що перший коміт не згадує Claude.
6. Ви: `nvm use`; `cp .env.example .env` і заповнити те, що назве підсумок; з БД `pnpm run db:up`, після першої моделі `pnpm run db:migrate`, зупинити `pnpm run db:down`; перший коміт на ваше слово.
7. Перша задача: рядок у «Далі» STATUS і пропозиція нової сесії.

Типи: API на Fastify чи NestJS, фулстек React і Vite, інтеграція чи cron, Telegram-бот; за потреби Postgres і Prisma. Модулі лише тоді, коли вже знадобились, з рядком «Нестандартне» в картці: `--module pgvector` (вектори в тій самій БД) і `--module budget` (денний ліміт витрат на платні API).

**Режими теки.** `python3 -I ~/.claude/skills/new-project/scaffold.py . --inspect` лише дивиться.
- Нова (порожня, крім `.git`, `.idea`, `.claude`, `brief/`): каркас.
- Заготовка IDE (до 40 файлів, не більше одного коміту): після вашого «так» її файли переносяться в `~/claude-backups/<дата>/new-project-<тека>-<час>/`, нічого не видаляється, далі каркас. Бекап видаляєте самі.
- Наявний проєкт: «прийняти в стандарт», код не змінюється. Claude створює лише те, чого бракує: картку, STATUS, скелет `docs/` і звіт розривів `docs/standard-gaps.md` (Node, захист від скриптів встановлення, lockfile, точні версії, `run check`, ESLint, strict, `.env.example`, Dockerfile, compose). npm чи yarn зі своїм lock-файлом це не розрив, а примітка. Хід закінчується списком розривів; ви кажете, які брати, і кожен стає задачею в новій сесії. Не коміт, не встановлення, не гейти.

**Бриф.** Бриф з чату Claude кладе в `brief/chat.md`, файли з ваших шляхів копіює в `brief/` скриптом `brief_check.py save` (без shell, нічого не перезаписує). `brief/` лишається лише у вас: git, Docker-образ і ESLint її не бачать; оригінали тримайте і деінде, бо `git clean -fdx` її видалить.
- Читає md, txt, csv, json, yaml, html, eml, pdf і картинки напряму, docx, doc, rtf і odt через textutil macOS; xlsx і pptx просить зберегти як PDF; посилань не відкриває. На симлінках і файлах-інструкціях для AI (`CLAUDE.md`, `AGENTS.md`, `.claude`) зупиняється. Текст у брифі, звернений до AI, не виконує, а цитує вам.
- Після створення: `docs/requirements.md`, запис у `docs/decisions.md` з причинами й альтернативами, розділи в `docs/integrations.md` з пунктами контракту «не вирішено».
- `docs/` іде в git, тож перед підсумком `brief_check.py` перевіряє, що там немає цін, телефонів, email, IBAN і карток, кодів ЄДРПОУ й ІПН, посилань, секретів, назви клієнта й імен людей з брифу. Логіни й паролі з брифу Claude не повторює, а радить перенести в менеджер паролів і попросити клієнта змінити.

**Стандарт.** Node 26, TypeScript 6, ESLint з перевіркою типів, Vitest, pnpm 12; пакети не виконують скриптів встановлення, поки ви не дозволите. Dockerfile у три етапи з запуском від користувача node, compose з `cap_drop: ALL`, `no-new-privileges` і лімітом логів, журнал JSON, коректна зупинка за SIGTERM; API і фулстек за Traefik без відкритого порту. З БД Postgres 18 і Prisma 7, міграції в git і на старті контейнера. Версії точні (`versions.json` скіла) і разом перевірені `tests/new-project-test.sh`; оновлюються лише релізом бази.

**Старі проєкти.** Проєкт на npm чи yarn лишається на своєму менеджері: «Package manager per lockfile» глобальних правил. Перехід на pnpm лише окремою задачею з вашого OK і окремим комітом: Claude спершу називає ризики (фантомні залежності, пакети зі скриптами встановлення), далі `pnpm import`, гейти, потім Dockerfile, CI і скрипти деплою. Оновлення до Node стандарту: пропозиція node-std чи «онови проєкт до стандарту Node за upgrade.md», лише в окремій сесії. Порядок у `~/.claude/skills/new-project/upgrade.md`: спершу Node, потім pnpm, потім мажори пакетів по одному; кожен крок окремий коміт після гейтів, `docker build` і osv, на ваше слово. Сервер, що збирає через npm, і Node на сервері міняєте ви.

## 5. Картка проєкту і блок «Розмір»

**Де.** Розділ `## Розмір` у корені проєкту, переважно в `CLAUDE.local.md` (у git не йде), інколи в CLAUDE.md чи AGENTS.md. `/new-project` пише картку сам; вона починається блоком «З чого почати»: де STATUS, індекс docs, команди.

**Що в ній.** Рядок «Рівень · Ризик · Дані · UI», далі «Етап», «Гейти етапу», «Успіх етапу», «Цифри», «Не додаємо», «Люки», «Нестандартне», «Переглянути, коли».
- T0 скрипт, T1 бот чи інтеграція, T2 застосунок з логінами і модулями, T3 кілька застосунків зі спільним кодом.
- R0 нічого з нижчого; R1 звичайні персональні дані чи запис назовні; R2 гроші (оплати, рахунки), договори, особливі персональні дані або ключ з правом запису в акаунт клієнта.
- V0 до 100 тис. рядків, V1 до 5 млн, V2 більше.
- UI A десктоп, B працює на телефоні, none без інтерфейсу.
- «Етап»: демо, пілот чи прод. `Етап: демо` вмикає легкі гейти `~/.claude/rules/demo-gates.md` замість глобальних правил про рев'ю, тести, перевірки й документи; пілот і прод ідуть за глобальними правилами повністю. На старті проєкту демо стає продом, і наступна задача це «зміцнення».
- «Не додаємо»: чого не робити. «Люки»: шляхи росту без переписування, наприклад «worker через env-прапорець, той самий image»; лише під них Claude може заздалегідь закласти шар. «Переглянути, коли»: коли настав час рости.
- «Нестандартне»: усе понад тип стандарту з причинами; кожна сесія бачить це як узгоджене.
- `UI-джерело:` (проєкти з інтерфейсом): звідки компоненти, наприклад чистий React, свої компоненти, шаблон чи дизайн клієнта, UI-кіт.

**Навіщо.** Claude бере з картки обсяг рішення і перевірки (телефон для UI B), code-reviewer дає HIGH за те, що картка забороняє, реєстр часу бере рівень для оцінок.

**Як змінити.** У сесії проєкту: «зміни в картці Розмір: <що>, бо <причина>». Переглядайте картку, коли настала умова з «Переглянути, коли», і перед оцінкою нового етапу.

## 6. Як змінювати налаштування

- Керовані файли (`~/.claude/CLAUDE.md`, `settings.json`, хуки, rules, скіли й агенти бази, `~/AGENTS.md`, `~/bin`) напряму не правте. Пряма правка Claude питає дозволу: відповідайте «ні» і робіть зміну одним зі способів нижче.
- Своє для всіх проєктів (мова, стиль, інструменти, правило): `~/.claude/rules/<своє>.md` без `paths:`, такий файл Claude Code вантажить на старті кожної сесії. Назва не має збігатися з правилом бази. Своє для проєкту: `<проєкт>/.claude/settings.local.json` і інструкції проєкту. Докладно: README, «Особистий шар».
- Дрейф: install зупинився з кодом 3, бо керований файл змінено повз базу; `doctor.sh --live` називає такі файли. У `settings.json` пише і застосунок (плагін, дозвіл «завжди», тема), це теж дрейф. Перенесіть свою зміну в особистий шар, потім `--force-drift`: змінений файл лишиться в знімку.
- Свої хуки, rules чи скіли в самій базі: форк і цикл з [FORK.md](FORK.md).
- Оновлення: README, «Оновлення». Після кожного install перезапустіть усі сесії Claude: нові правила й хуки діють лише в нових сесіях.
- Відкат: `bash scripts/rollback.sh <попередній тег>` і перезапуск сесій. Знімки: `ls ~/claude-backups/setup-snapshots/`. Аварійні випадки: README, «Відкат».
- ECC: `~/bin/ecc-drift.sh` показує розбіжності з upstream; локальні відмінності в `vendor/ecc/patches/`, перелік у `vendor/ecc/ECC-PIN.md`. Що переносити, вирішую я; зміни приходять наступним тегом.
- Пропозиції змін: issue чи PR (README, «Внески»).

## 7. Шпаргалка команд

Стан бази (лише читає):
```bash
cd ~/claude-code-base && bash scripts/doctor.sh --live --skip-tests
```
Один проєкт поводиться не так, як решта (лише читає):
```bash
cd ~/claude-code-base && bash scripts/project-doctor.sh <тека проєкту>
```
План встановлення тегу (нічого не пише):
```bash
cd ~/claude-code-base && bash scripts/install.sh <тег> --dry-run
```
Відкат на попередній тег:
```bash
cd ~/claude-code-base && bash scripts/rollback.sh <попередній тег>
```
Години за проєктами з дати:
```bash
~/bin/claude-time --by project --since <YYYY-MM-DD>
```
Медіана і p75 за типом задачі:
```bash
~/bin/claude-time --by kind
```
Сесії, ще не поділені на задачі:
```bash
~/bin/claude-time --pending
```
Метрики «до і після» у ваших вікнах:
```bash
~/bin/claude-metrics --before <від> <до> --after <від> <до>
```
Метрики по тижнях:
```bash
~/bin/claude-metrics --weekly
```
Розбіжність ECC з upstream:
```bash
~/bin/ecc-drift.sh
```
ТЗ з Markdown у Word і PDF:
```bash
python3 -I ~/.claude/skills/client-tz/md2docx.py <файл>.md <файл>.docx --strict --pdf
```
Що піде з проєкту в репо документів (нічого не пише):
```bash
~/.claude/hooks/docs-sync.sh connect --dry-run ~/WebstormProjects/<тека>
```
Підключити проєкт до репо документів:
```bash
~/.claude/hooks/docs-sync.sh connect ~/WebstormProjects/<тека>
```
Синхронізувати документи проєкту зараз:
```bash
~/.claude/hooks/docs-sync.sh sync ~/WebstormProjects/<тека>
```
Стан репо документів (лише читає):
```bash
~/.claude/hooks/docs-sync.sh report
```
Перевірка репо для своєї копії ([FORK.md](FORK.md)):
```bash
cd ~/claude-code-base && bash scripts/verify.sh
```
