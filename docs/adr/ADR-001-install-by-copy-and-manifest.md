# ADR-001: встановлення копією з маніфестом, а не symlink чи плагіном

- Статус: прийнято 2026-10-12

## Контекст

`~/.claude` діє одразу на всі проєкти. Якщо правити його напряму, немає ні історії, ні тестів, ні відкату. Потрібен спосіб, за якого живий стан точно відповідає одній перевіреній версії, а невдалий реліз відкочується однією командою.

## Рішення

Репо є джерелом правди. `scripts/install.sh <тег>` розпаковує тег у тимчасову теку (`git archive`), проганяє `verify.sh`, робить знімок і **копіює** у живі шляхи лише керовані елементи. Їхній список виводиться з розкладки репо (`scripts/lib.sh`, `managed_items`), тож окремого списку, який міг би розійтися з файлами, немає. Після встановлення пишеться `~/.claude/.setup-manifest.json` з sha256 кожного файла (для `settings.json` хеш береться від `jq -S -c .`).

## Розглянуті варіанти

| Варіант | Плюси | Чому ні |
|---|---|---|
| **Копія з маніфестом (обрано)** | Тег точно відповідає живому стану. Видно дрейф, коли застосунок сам пише в `settings.json`. Відкат детермінований. Нічого не треба встановлювати | |
| Особистий плагін | Вмикання по проєктах | Скіли й агенти стають `/<плагін>:<назва>`, маршрутизація в CLAUDE.md і звички ламаються. `settings.json` і CLAUDE.md однаково мають бути справжніми файлами. Незавершені правки одразу діють у всіх сесіях |
| Symlink на робоче дерево | Просто | Кожна напівготова правка одразу діє на всі проєкти. Поведінка застосунку при записі в symlink-файли не задокументована. `/rewind` такі файли пропускає |

## Наслідки

- Живі файли не редагуються напряму: зміна це коміт, тег, install.
- Дрейф (зміна живого файла поза базою) видно при install і в `doctor.sh --live`.
- `~/.config/git/ignore` зливається по рядку і ніколи не перезаписується: Claude Code сам дописує туди рядки. Відсутні рядки бази дописуються в кінець; прибирає база лише рядки, які сама дописала (`merge_owned` у маніфесті) і яких новий тег уже не має. Рядків, що були у файлі до бази, вона не прибирає ніколи.
- Install нічого не видаляє через `rm`: витіснене переноситься в знімок. Якщо встановлення падає після знімка, `restore.sh` цього знімка запускається сам.

## Коли переглянути

- Котромусь проєкту знадобиться інший набір хуків.
- Власних скілів стане п'ять і більше.
- З'явиться другий комп'ютер (тоді git marketplace).
