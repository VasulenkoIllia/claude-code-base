## v2026.11.33 (реліз 1.3: один файл походження вендорених файлів; основа для бібліотеки паків)

- Цей тег вийшов як GitHub Release «1.3».
- `vendor/ecc/items.tsv` переїхав у `vendor/items.tsv` і має новий формат: рядок на кожен вендорений файл з класом (`patched` чи `verbatim`), джерелом, повним піном коміту, шляхом у джерелі, ліцензією і датою перегляду. `verify.sh` перевіряє, що кожен вендорений файл має рядок і кожен патч названо. `THIRD_PARTY_NOTICES.md` посилається на новий шлях.
- У моїй базі з'явилась бібліотека паків: плагіни Claude Code, які вмикаються по проєктах. У публічну версію вона не входить. Спільний код встановлення про неї знає і без теки `packs/` мовчить: `install.sh` і `doctor.sh` працюють, як раніше, а `verify.sh` має нову перевірку `packs and catalog`, яка тут каже `no packs/ in this tree`.
- Правила, хуки, агенти, скіли, дозволи й інструменти ті самі, що у v2026.11.32: оновлення не змінює в `~/.claude` нічого, крім тегу в маніфесті.
- Після оновлення нічого робити не треба. Якщо у своїй копії ви дописували рядки у `vendor/ecc/items.tsv`, перенесіть їх у `vendor/items.tsv` у новому форматі: колонки називає перший рядок файла, порожнє поле це `-`.

## v2026.11.32 (реліз 1.2: git з перекладом більше не зупиняє встановлення; уточнення README за звітом першого встановлення)

- Цей тег вийшов як GitHub Release «1.2».
- docs-sync: git у ньому тепер завжди відповідає англійською (`LC_ALL=C` у середовищі кожного його виклику git). Раніше з git, який має переклад (Homebrew git з неанглійською локаллю системи), перевірка перед встановленням падала на `FAIL docs-sync push by hand`, і install відмовляв, нічого не записавши; а клас збою пушу в лозі docs-sync не визначався. Синхронізація документів працює, як працювала: назв файлів і повідомлень комітів кирилицею зміна не зачіпає. Рядок `last commit ... ago` у `doctor.sh --live` тепер англійською і з перекладеним git.
- README українською й англійською, за звітом першого встановлення на чужій машині: у «Вимогах» типова причина, чому `command -v python3` друкує не `/opt/homebrew/bin/python3`, і як це виправити; крок 1 «Першого встановлення»: теку створює `git clone`, а команди вже мають `cd`; крок 7: команду `git commit --no-verify -m test` має запустити Claude в сесії, у терміналі її не запускайте.
- Правила, агенти, скіли, дозволи й решта хуків ті самі, що у v2026.11.31.
- Після оновлення: якщо ви запускали `install.sh` чи `doctor.sh` з префіксом `LANGUAGE=en LC_ALL=en_US.UTF-8` або дописали заради бази `export LC_MESSAGES=en_US.UTF-8` у `~/.zshrc`, це більше не потрібно: оновлюйтесь за розділом README «Оновлення» без префікса. Я перевірив зміну на підставному git, що відповідає українською; справжнього git з перекладом у мене немає, тож якщо `--dry-run` знову покаже `FAIL`, напишіть мені в Issues.

## v2026.11.31 (реліз 1.1: хук push-allow, блок друку env-файлів, effort рев'юерів; релізи виходять одразу)

- Цей тег вийшов як GitHub Release «1.1». З нього публічний реліз виходить одразу після кожного релізу моєї бази, а GitHub Release на кожен тег, з назвами підряд: 1.2, 1.3 і далі. Версією для оновлення лишається тег calver `vYYYY.MM.N`. Тегів v2026.11.29 і v2026.11.30 тут немає: їхні зміни входять у цей реліз.
- Хук `push-allow` (подія PermissionRequest): `git push origin <feature-гілка>` іде без вікна дозволу, коли хук прочитав усю команду, а решта команд у ній зі списку безпечних. Push у main, master, develop, staging та інші захищені гілки, push тегів, без назви гілки, з `-C` і в інший remote питає, як і раніше. Умови: `docs/USAGE.md`, розділ 2.
- bash-guard: друк env-файла (`cat`, `head`, `tail`, `less`, `grep`, `sed`, `awk` на `.env` і файлах `<назва>.env`) і `docker compose config` тепер блокуються з підказкою, яка форма проходить; раніше це був запит. Проходять файли-зразки (`.env.example`), тихі форми на кшталт `grep -c KEY .env`, вивід із маскою після `|` і `docker compose config -q`. `rm -r` блокується ще й у формах `\rm`, `/bin/rm`, у дужках і на теках першого рівня дому.
- settings: Claude не читає `.env.staging`, `.env.stage`, `.env.development`, `.env.dev`, `.env.test` і файли `*.env`; запит дозволу на `gh repo create --public`, `gh repo edit --visibility`, `git -C <тека> push` і термінал застосунку.
- session-hint: після зеленого CI Claude одразу викликає `gh pr merge`, вікно дозволу і є вашим рішенням.
- Шість агентів-рев'юерів працюють з `effort: xhigh`. Прибрано два вендорені скіли ECC, якими я не користувався: api-design і documentation-lookup; install прибере їх з `~/.claude/skills`, копія лишиться у знімку.
- doctor: рядок `docs state` на проєкт (завеликий STATUS, журнал чи memory) і рядок `docs repo origin` (чи приватний репо, куди docs-sync пушить документи). Глобальний файл правил коротший на 154 байти.
- Після оновлення перезапустіть усі сесії Claude: нові дозволи й хук `push-allow` діють лише в сесіях, стартованих після install. Якщо блок друку env-файлів заважає: `bash scripts/rollback.sh v2026.11.28`.
